## Private natural-factory linkage experiment

The earlier hidden-definition counterexample remains valid: ordinary ClassFileTransformer callbacks do not provide hidden lambda bytes, and a shared nest host does not identify a function's body. This continuation explores a different observation point: the original JVM LambdaMetafactory call site, reached through the real factory during natural binding.

The optional private agent recognizes only a constrained noncapturing, static-implementation `LambdaMetafactory.metafactory` shape in requested definitions. It redirects that bootstrap to a small JDK-only bridge. The bridge calls the original JDK metafactory with the original Lookup, SAM types and implementation MethodHandle, then records the exact function returned by the original call-site target. It returns that same function; it does not call its ticker body, construct a replacement ticker, or invoke an unproved Mod factory during lookahead.

A descriptive origin entry binds the actual object by reference to the actual caller Class/loader/module, direct implementation owner/name/descriptor/reference kind, SAM type and function Class. Original-lookup/full-privilege and call-site metadata are checked. StackWalker class identity, method descriptor and actual bytecode offset must match the observed invokedynamic instruction in the returned definition. Re-reading the rewritten class accounts for constant-pool changes affecting instruction offsets.

The bounded registry accepts only actual JVM transformer invocations and its installed publisher; external metadata publication and direct calls to the transformer do not create observations. It refuses duplicate/redefined/ambiguous or excessive definitions, captures only supported function shapes, and requires one known startup agent with attach disabled. Requested names select observation locations; they grant no Mod execution permission. None of these checks is a Core Closure Verifier.

The final experiment also records the selected source's ordinary definition without modifying its body. Before the controlled external actor runs, an exact normalized method snapshot must match the independently audited original counter method, and the prospective value must avoid the periodic service branch. Snapshot comparison controls this negative test only; it does not issue Proof, Claims or Worker permission. The snapshot class bytes are never loaded as a replacement implementation.

ModLauncher's game module loader could not see the first app-loader-only helper. The repaired experiment puts only the JDK bridge in a separate bootstrap-search jar, gives the affected named module the required read edge, and isolates its ASM implementation. This remains a local experiment; no bootstrap/build/settings, default launch path or runtime API change is shipped. Its module/classloader compatibility is not a claim of production readiness.

The origin record is ordinary descriptive data. It has no Ticket, Permit, scheduler, executor, Claim, Reservation, Lease, Scope or effect-commit surface. There is no Core consumer that promotes it into a trusted manifest. The registry stores bounded code/function metadata, not a Level, BE or captured source object.

## Real Mod/Level tests and writer result

The first test reads the actual function inside the original LevelChunk delegate from the production-admitted body observer. It does not obtain a substitute function by calling getTicker during preparation. Two actual original folding stools are placed across a real fixed Region boundary in one ServerLevel. Every counted original canonical body has the corresponding actual-function observation. Each source advances at least40times, traversing multiple periodic maintenance boundaries; complete body, private-counter delta and linked-body totals must match. Every canonical Mod ticker remains serial.

That body observer runs after production admission with the original Permit already started. Its observations validate the experiment; they cannot become a pre-start Worker grant. A future Core backend must use the actual immutable linkage record plus fresh complete source/storage/lifecycle proofs before the original Ticket enters RUNNING. The current C5 inspection inside a started Serial Permit cannot be promoted.

The second test uses a separate test-created external actor. The adapter only signals and awaits it; the adapter does not create a thread or executor. The actual registered source is paused inside the original canonical Serial Permit, before its original ticker body. After checking the observed runtime writer method against the audited original and choosing a nonperiodic counter value, the actor directly invokes the original public maintenance method once. It has no Kernel Permit, Resource Scope or native Worker identity. Main waits for physical actor exit before the original serial ticker continues.

Observed result: the external method changes the real counter by1. The following canonical ticker changes it once more: canonicalBodies1, finalCounterDelta2. Both are separately counted; the direct method call is not called a Worker grant, an authorized ticker invocation or a replay.

This test demonstrates that **being inside a canonical phase does not exclude an unparticipating public writer**. It does not acquire a Mod Lease and does not claim a bug in the existing Lease implementation, a demonstrated race during a reserved Worker, lost updates, general rollback, or an actual upstream asynchronous counter writer. It is a concrete counterexample to treating the phase/fresh snapshot/origin description alone as sufficient exclusion.

The remaining architectural obligation is independent writer participation/exclusion on the actual storage, covering public entries, callbacks, dynamic dispatch, asynchronous routes, lifecycle and all reached runtime code. Existing Claims serialize participating reservations; they do not turn an ordinary Mod field into protected memory. A freshness predicate can detect a change before body but cannot prevent a later writer. A Dedicated assertion or names/hash allowlist cannot fill this gap. A partial field hook or second resource lock would not establish the requested complete proof.

The next implementation must use the existing ownership/kernel authority and establish that complete boundary before any original Ticket starts. That design and its safety proof remain unimplemented. This continuation does not force an immature guard or start C6.3 on top of an assumption.

Review of the existing `Scope.require`, one-shot Lease, original admission binding and canonical prefix lifecycle leaves these specific design obligations:

| Proposed shortcut | Boundary a complete implementation must establish |
|---|---|
| Reserve a boxed counter or an adapter wrapper | The actual field belongs to the original source object. A source-object claim must cover all relevant writers to that containing root, including lifecycle and other instance state. |
| Check only current Level/home or thread identity at one point | Original source identity must remain attached to the correct original phase and ownership through replacement/unload; mutable binding state must not make an active original root appear unowned. |
| Allow a server write when no Scope/Guard is currently entered | Published or accepted-but-not-started work still requires exclusion. Idle thread-local state is not physical join; required commit and the original outer lease lifetime still matter. |
| Add a hook at one ticker entry or selected PUTFIELD | Other public entries, aliases, inherited state, dynamic/reflective access and asynchronous routes need independent closure/participation verification. Unproved routes must refuse, not inherit a field-name certificate. |

These are unresolved implementation/proof obligations. The new negative test reproduces the public-entry gap only; it does not claim to reproduce all rows or prove that a future general solution is impossible. No second resource lock, reservation map or authority is introduced as a substitute.
